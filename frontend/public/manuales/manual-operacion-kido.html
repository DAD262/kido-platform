Cómo iniciar, revisar y apagar KIDO

Manual práctico para ejecutar el frontend, la infraestructura y cada microservicio sin perderse entre carpetas, puertos o dependencias.

Frontend :4300Gateway :18080Keycloak :19090Docker ComposeMercado Pago en pruebas

1. Qué inicia KIDO

El navegador entra por Angular. Las llamadas de negocio pasan por el Gateway y este localiza los microservicios registrados en Eureka.

Flujo principal: Navegador → Angular :4300 → Gateway :18080 → microservicios → PostgreSQL/Kafka. El inicio de sesión se realiza mediante Keycloak :19090.

Infraestructura

Config Server, Eureka, Keycloak, Kafka, Mailpit, PostgreSQL, Prometheus y Grafana.

Negocio

Cursos, inscripciones, pagos, usuarios y notificaciones, detrás del Gateway.

2. Antes de iniciar

Abre Docker Desktop. Espera hasta que el motor indique que está listo.
Abre PowerShell. Define una variable para no repetir la ruta.
Comprueba .env. Debe existir en la raíz, pero nunca debe compartirse ni subirse a GitHub.
$KIDO = "C:\Users\ASUS\OneDrive\Documentos\KIDO_Acceso_v4\kido-platform"
Set-Location $KIDO
docker version
node --version
java --version
Si Docker responde que no encuentra dockerDesktopLinuxEngine: Docker Desktop todavía no está iniciado.

3. Iniciar el sistema completo

3.1 Backend e infraestructura

Set-Location $KIDO
docker compose up -d --build
docker compose ps

La primera ejecución puede tardar porque Docker descarga imágenes y Maven instala dependencias.

3.2 Frontend Angular

Ejecuta esto en una segunda terminal:

Set-Location "$KIDO\frontend"
npm.cmd install
npm.cmd start
Cuando Angular muestre que compiló correctamente, abre http://localhost:4300.

7. Diagnóstico y registros

Estado general

Set-Location $KIDO
docker compose ps
docker compose config --services

Registros

docker compose logs -f
docker compose logs -f kido-config
docker compose logs -f kido-eureka
docker compose logs -f kido-keycloak
docker compose logs -f kido-pago-ms
docker compose logs -f kido-gateway
Ctrl + C en docker compose logs -f solamente deja de seguir los registros; no apaga los contenedores.

Errores comunes

MensajeCausa probableAcción
Connection refused al Config ServerConfig Server apagado o puerto incorrectoInicia kido-config; usa 18889 en Docker y 18888 en Java local.
Docker engine no encontradoDocker Desktop apagadoInicia Docker Desktop.
Puerto 4300 ocupadoOtro frontend KIDO ya está activoDetén el proceso anterior; KIDO no cambia automáticamente de puerto.
Servicio no aparece en EurekaNo inició o no obtuvo configuraciónRevisa sus logs y luego los de Config/Eureka.

8. Apagar KIDO correctamente

Conservar bases y contenedores

Set-Location $KIDO
docker compose stop

Retirar contenedores conservando los datos

docker compose down

Detener o reiniciar una sola pieza

docker compose stop kido-pago-ms
docker compose restart kido-gateway
docker compose restart kido-keycloak
Operación destructiva: docker compose down -v elimina los volúmenes locales: usuarios, cursos, pagos y demás datos. Úsalo únicamente si deseas reiniciar KIDO desde cero.

12. Seguridad y archivos privados

  • No publiques .env.
  • No pegues tokens, claves de Mercado Pago ni contraseñas en capturas.
  • No incluyas secretos en archivos YAML versionados.
  • Usa .env.example solamente como plantilla sin valores reales.
  • Antes de subir a GitHub, ejecuta git status y revisa exactamente qué archivos se incluirán.
Set-Location $KIDO
git status --short
git check-ignore .env
