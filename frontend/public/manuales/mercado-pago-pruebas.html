1. Introducción

KIDO integra Mercado Pago como proveedor externo. La plataforma conserva la orden académica y comercial; Mercado Pago procesa los datos sensibles del medio de pago.

Regla principal: el frontend nunca decide que una compra fue aprobada. El backend consulta Mercado Pago y valida estado, referencia, moneda, monto, receptor y ambiente.

1.1 Propósito de aprendizaje

✓Configurar credenciales sin exponer secretos.
✓Comprender preferencia, retorno y webhook.
✓Interpretar las líneas reales de Java y TypeScript.
✓Probar aprobación, rechazo y estado pendiente.

5. Implementación backend Java

5.1 Cliente HTTP

RestClientConfig.java
@Bean
RestClient mercadoPagoRestClient() {
  var http = new SimpleClientHttpRequestFactory();
  http.setConnectTimeout(Duration.ofSeconds(5));
  http.setReadTimeout(Duration.ofSeconds(20));
  return RestClient.builder()
      .requestFactory(http)
      .baseUrl("https://api.mercadopago.com")
      .build();
}
LíneaExplicación
@BeanRegistra el cliente para inyectarlo.
setConnectTimeoutEvita esperar indefinidamente al abrir conexión.
setReadTimeoutLimita la espera de respuesta.
baseUrlCentraliza el dominio oficial.

6.3 Lista blanca del dominio

checkout.ts
const DOMINIO_MP =
  /^https:\/\/([a-z0-9-]+\.)*mercadopago\.com(\.[a-z]{2})?\//i;

export function esCheckoutMercadoPago(url: string) {
  return DOMINIO_MP.test(url);
}
Resultado: KIDO solo navega a un dominio admitido y el backend continúa siendo la única autoridad para aprobar.

9. Criterios de aceptación

✓Access Token únicamente en backend.
✓Preferencia creada en PEN con monto del servidor.
✓Redirección limitada a Mercado Pago.
✓Backend consulta /v1/payments/{id}.
✓Webhook firmado y reconsultado.
✓Solo approved habilita acceso.

11. Recomendaciones

Para la demostración: mantener el ambiente en pruebas, simulación deshabilitada, webhook firmado y comprador en incógnito.
  1. No registrar cuerpos completos que contengan datos personales.
  2. Probar doble clic, timeout y webhook repetido.
  3. Rotar cualquier credencial expuesta accidentalmente.
  4. No pasar a producción cambiando solamente el token.
  5. Antes de producción: HTTPS estable, secretos administrados, monitoreo, conciliación, reembolsos y revisión legal.
  6. Evaluar a futuro Checkout Pro vía Orders API conservando idempotencia y compatibilidad histórica.
